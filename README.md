> Vibe 2.0：AI 引导意图，人做决策，AI 执行，把模糊变成具体。

**让人说清楚、选明白、做得到。**

一套把模糊感觉变成清晰选择、可靠工作流和可复用能力的人机协作技能集。

`Agency-Craft` 不是提示词合集，也不是让 AI 更大胆地替人做决定。它由三个可独立使用的 Codex 技能组成：帮助人说清楚自己想要什么，帮助 AI 选出完成目标所需的最小能力组合，并把经过验证的方法沉淀成更多人能稳定使用的技能。

安装后，不必背命令。直接用自然语言描述你的困惑，匹配的技能会根据意图触发。

---

## 为什么需要它

我们常说 AI 能解决很多问题，但真正驾驭 AI 时，瓶颈往往不在模型，而在人与模型之间的意图摩擦。AI 的执行能力越来越强，但执行速度不能补偿方向错误：

- 人知道自己“不满意”，却说不清理想结果是什么。
- “可爱、漂亮、高级、自然、专业”等词高度模糊，不同的人指向完全不同。
- 模糊意图直接进入执行，会产生大量试错、反复改稿、低质量作品和无效 Token 消耗。
- 技能越多，选择、排序、交接和恢复上下文的成本越高。
- 第一版技能通常建立在未经验证的假设上，写完并不等于可靠。

`Agency-Craft` 把这些摩擦固定成三个可触发的决策点：**先澄清意图，再组织能力；需要复用时，再把经验锻造成技能。**

---

## 核心方法：从 Vibe 到 Agency

Vibe 2.0 不是让 AI 更大胆地猜，而是一套可行的人机交互闭环：

```text
模糊愿望
  → AI 帮助人观察、学习和比较
  → 人选择真正想要的方向
  → AI 将选择写成可执行、可验收的意图规格
  → AI 裁决最小能力组合与关键路径
  → 领域技能或工具执行
  → 人依据标准验收
  → 证据回流，改进下一次协作或技能
```

核心分工始终保持：

> **AI 引导，人决策；AI 执行，人验收。**

这里的 **Agency** 指人的能动性：人能够觉察差异、理解选择、决定方向，并塑造自己想要的世界。它不是把决定权交给 Agent。

三个技能对应三道独立闸门：

| 闸门 | 要回答的问题 | 技能 | 核心产物 |
| --- | --- | --- | --- |
| **Intent** | 执行者还需要猜测人的高影响价值判断吗？ | [`Vibe-Craft`](skills/vibe-craft/) | 意图规格、Vibe Map、边界与验收标准 |
| **Flow** | 每个候选技能都必要，而且处在正确顺序吗？ | [`Vibe-Flow`](skills/vibe-flow/) | 技能裁决、关键路径、交接物与执行闸门 |
| **Capability** | 这个方法经过真实测试，能让其他人稳定使用吗？ | [`Skill-Craft`](skills/skill-craft/) | 经测试的技能、案例与可复用模式 |

这不是必须走完的流水线。目标已经清晰，就跳过 `Vibe-Craft`；只有一个能力足以完成，就让 `Vibe-Flow` 直接采用它；不需要长期复用，就不必启动 `Skill-Craft`。

## 三个技能

### Vibe-Craft · 把感觉变成决定

用于“我知道想改变，但说不清具体要什么”的场景。

它先观察已有对象，再把“更高级”“更自然”“感觉不对”等模糊词拆成与当前领域相关的维度；提供两到四个有意义的对照方向，让人做价值选择，最后生成可以直接交给执行者的意图规格。

主要产物：

- 当前状态与目标状态。
- 有参照依据的 Vibe Map。
- 必须保留、必须避免和暂不处理的边界。
- 按 P0 / P1 / P2 排序的改变建议。
- 可观察、可测试的验收标准。

### Vibe-Flow · 让能力选明白、组织好

用于“我有很多技能，但不知道该用谁、怎么组合、先做什么”的场景。

它把每个候选技能送上对抗式审理：先提出最强反对理由，再要求它用触发条件、独特价值、输入、输出、权限与交接证据自证必要。幸存技能按华罗庚式统筹方法组成关键路径、并行支线和最少闸门；当用户要求执行时，工作流会在权限范围内继续推进，而不是把计划重新丢给用户。

主要产物：

- Required / Conditional / Parallel / Later / Reject 裁决。
- 一条真实依赖组成的关键路径。
- 每一步可直接消费的交接物。
- 继续、重审和停止的证据标准。

### Skill-Craft · 把一次方法变成可靠技能

用于创建新技能、改进现有技能或调试技能质量。

它把第一版视为待证伪的假设，而不是成品。流程从问题建模开始，经过草稿、独立真实测试、P0 / P1 / P2 审计、减法和通用化；案例进入经验库，案例中反复成立的判断再提炼为模式。

主要产物：

- 作用域明确、触发条件清晰的技能。
- 独立测试暴露的问题与修复证据。
- `references/cases/` 中的真实案例。
- `references/patterns/` 中可继续验证的决策规则。

## 快速安装

克隆仓库：

```bash
git clone https://github.com/AdgaiWalker/Agency-Craft.git
cd Agency-Craft
mkdir -p ~/.codex/skills
```

在 macOS / Linux 上按需链接一个或多个技能：

```bash
ln -s "$PWD/skills/vibe-craft" ~/.codex/skills/vibe-craft
ln -s "$PWD/skills/vibe-flow" ~/.codex/skills/vibe-flow
ln -s "$PWD/skills/skill-craft" ~/.codex/skills/skill-craft
```

如果目标路径已经存在，跳过对应命令，或先确认它是否是你正在使用的版本。重新启动 Codex 或开启新任务后即可使用。

## 怎么用

直接描述目标，不需要先学习专业术语：

```text
这个杯子我想让它更可爱，但不要幼稚。我说不清该改哪里。
→ Vibe-Craft

我准备从零设计一个网站，这些设计和动画技能应该怎么组合？直接帮我推进。
→ Vibe-Flow

把这套反复使用的方法做成一个别人也能稳定使用、可以继续迭代的技能。
→ Skill-Craft
```

需要显式指定时，可使用：

```text
使用 $vibe-craft，把这个模糊感觉澄清成可执行、可验收的意图规格。
使用 $vibe-flow，审理这些候选技能并直接推进最小可靠工作流。
使用 $skill-making-skill，把这套方法做成经过真实测试、可以继续迭代的技能。
```

## 设计原则

- **先澄清，再执行**：执行速度不能补偿方向错误。
- **用对照激发觉察**：不给人出抽象术语考试，而是提供可比较的具体方向。
- **提供刚好够用的知识**：只补充下一项决策真正需要的知识。
- **人决定价值，AI 负责执行**：AI 可以扩展选项、指出矛盾和预测后果，但不能替人决定什么值得追求。
- **对抗错误假设**：每个需求、技能和工作流都要回答它是否必要、是否重复、是否过早，以及什么证据会证明它错了。
- **每轮减少下一轮成本**：留下意图规格、裁决、验收标准、案例或模式，而不是每次从模糊对话重新开始。

## 仓库结构

```text
Agency-Craft/
├── skills/
│   ├── skill-craft/
│   │   ├── SKILL.md
│   │   └── references/
│   ├── vibe-craft/
│   │   ├── SKILL.md
│   │   ├── agents/
│   │   └── references/
│   └── vibe-flow/
│       ├── SKILL.md
│       └── agents/
├── LICENSE
└── README.md
```

每个技能都是自包含目录。`SKILL.md` 是执行规则；`agents/openai.yaml` 是用户界面元数据；`references/` 保存按需读取的模板、案例、模式或示例。

## 愿景

我们希望 AI 不只是替人快速生产世界，也帮助人更清楚地看见自己真正想创造什么。

当模糊可以被觉察，当感受可以被表达，当选择始终掌握在人手中，AI 的执行能力才不会放大噪声，而会放大人的创造力。

> 从模糊到具体，从被默认值牵引到主动选择，从消耗 AI 到真正驾驭 AI——这就是 Agency-Craft 想推动的 Vibe 2.0。

# 案例 002：side-hustle-blueprint

## 输入 X

- **什么技能**：帮用户从零到一规划并上线服务型副业
- **类型**：纯指导类
- **领域**：商业规划 / 副业

## 过程

### 被证伪的假设

| # | 假设 | 实际 | 后果 |
|---|------|------|------|
| 1 | 不需要分析用户身份就能推荐平台 | 不同身份（学生/商家）能开的店完全不同 | 用户可能走错平台，白费精力 |
| 2 | 定价只要看市场价就行 | 定价还取决于用户的时间成本和能力水平，新手不应降价 | 给了新手错误建议：降价。实际应按市场价定价，前期慢是投资不是亏损 |
| 3 | 所有用户都从"我会什么"出发 | 有些用户从"我看到市场机会"出发，路径完全不同 | 技能只服务了供给端用户，忽略了需求端用户 |
| 4 | 技能只服务"卖时间"一种模式 | 用户可能卖时间、卖产品、卖方案，每种定价逻辑不同 | 定价环节覆盖不全 |
| 5 | 所有图片都需要AI生成 | 很多场景直接截图/拍照就够了，大电商甚至不该用AI生图 | 给了不必要的生成建议 |
| 6 | SKILL.md应该包含所有知识 | 超过500行，知识塞主文件导致膨胀难维护 | 违反了自身方法论的500行限制 |

### 关键决策

1. **加身份匹配**：从"你会什么"改为先搞清"你是谁"——学生/商家/自由职业者能做的事完全不同
2. **加止痛药/维生素判断**：不是所有需求都一样，紧急痛点的服务最容易起步
3. **加信任体系**：需求匹配了但客户不信你，交易不会发生。信任是最后一公里
4. **双入口设计**：用户可以从"我会什么"或"我看到什么需求"两个方向进入，在需求匹配点汇合
5. **学习曲线定价**：新手前期慢是投资不是亏损，不应该因此降价。市场价就是合理价
6. **数据驱动受众推断**：不猜测客户是谁，从竞品评价、搜索词等真实数据中推断
7. **拆references**：平台规则、视觉生产指南拆到独立文件，主文件只保留决策逻辑和路由

### 迭代过程

```
v1（6阶段，单文件）
  → 用户反馈：为什么不上来就分析身份匹配平台？
  → 加身份匹配、平台决策树、可行性快算

v2（7阶段，+身份匹配+信任+止痛药）
  → 超过500行，开始膨胀
  → 加护城河、信任体系、竞品健康度检查

v3（7阶段，+商品展示素材）
  → 审理发现：行数超标、编号不统一、受众分析重复
  → 提取references，主文件降到435行

v4（8阶段，+视觉素材）
  → 用户试用反馈：定价不合理，新手不知道怎么定价
  → 改定价逻辑：市场价锚+时间成本底线+学习曲线+新手不降价

v5（+双入口）
  → 用户反馈：技能只服务"有技能的人"，忽略了"有市场洞察的人"
  → 加供给/需求双入口，在需求匹配点汇合
```

### 测试发现

- **用户试用**：定价环节不满意——上来就定最低价，新手不知道怎么定价
- **自身审理**：行数超标（547行）、3.3和7.1受众分析重复、"定规则"没有编号
- **深层洞察**：用户是两种人——懂技能的和懂市场的，但最终都要走到"需求匹配"

## 输出 Y

- `side-hustle-blueprint` 技能（SKILL.md 484行 + references/ 2个文件）
- 8阶段流程，双入口设计
- 推送到 `https://github.com/AdgaiWalker/Walker-skills-test`

## 产出（回流到 skill-making-skill 的规则）

| # | 规则 | 对应 SKILL.md 位置 |
|---|------|-------------------|
| 1 | SKILL.md是守门员不是知识库——决策逻辑放主文件，具体数据放references | Phase 2（草稿）"SKILL.md 不超过 500 行"的补充说明 |
| 2 | 纯指导类技能也需要拆references——平台规则、工具列表、模板都是"会过时的知识" | Phase 5（做减法）"迁移"的扩展适用范围 |

## 教训

这次最大的教训不是"副业怎么做"，而是对 **Skill 本质的分层理解**：

> Skill 不是单文件的提示词，是主文件及背后的整个生态。

主文件（SKILL.md）不是知识库，是**底线守门员和资源管家**：
- **守门**：什么必须问、什么不能跳过、什么原则不能违反
- **管资源**：这个问题去查哪个 references 文件
- **不装知识**：具体数据、模板、工具列表放 references

这个认知是被逼出来的——主文件膨胀到547行时，不得不拆分。拆完才发现主文件变得更清晰了：只有决策逻辑，没有信息噪音。

这印证了 Phase 5"做减法"的三把刀——但比"删"更深的理解是：**不是内容有问题，是内容放错了位置**。知识不是不需要，是不该放在守门员的位置上。

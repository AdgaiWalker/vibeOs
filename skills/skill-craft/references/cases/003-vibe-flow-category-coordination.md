# 案例 003：Vibe-Flow 范畴第一性与华罗庚统筹改造

## 输入 X

用户希望把以下思想纳入现有技能体系：

- 根据上下文组织视角互不重复的专家团；
- 每个专家从自己所属范畴的第一性原理独立推演；
- 区分不同范畴下的概率判断，最后共同指向同一对象；
- 用华罗庚统筹方法安排执行次序、并行关系、资源和动态重排；
- 同时检查 `vibe-flow` 与同目录的 `vibe-craft`、`skill-craft` 如何协作。

类型判定：纯指导类技能改造，同时涉及配对技能的契约与路由。

## 初始状态与被证伪的假设

旧版 Vibe-Flow 已有必要性裁决、单一关键路径和三道闸门，但存在五个结构问题：

1. 默认只有一条关键路径，不能表达多条互不争抢资源的主要矛盾线；
2. 用一个状态同时表达“技能是否必要”和“它放在执行网络哪里”；
3. 没有判断何时需要多范畴第一性推演，也没有明确何时必须跳过；
4. 专家视角、证据任务和实际执行任务容易混成同一种节点；
5. 仓库版本与实际 Codex 技能目录出现安装版本漂移，修改正确并不代表运行时会消费正确版本。

另一个被证伪的假设是：出现一套新的推理方法，就应当创建第四个顶层技能。实际裁决表明，它没有独立终态，也没有独立消费者；它应当成为 Vibe-Flow 在特定不确定性下调用的参考模块。

## 变换过程

### 1. 先裁决归属，不先扩展技能数量

- `vibe-flow`：拥有跨技能准入、执行位置、统筹网络和交接责任，因此负责条件化调用多范畴推理。
- `vibe-craft`：继续只负责人类拥有的审美、方向、取舍等高影响意图，不承接事实和因果推演。
- `skill-craft`：负责 RED/GREEN、无上下文独立测试、审计分级和经验沉淀。

主文件只保留触发闸门、路由和硬约束；详细推理格式下沉到
`vibe-flow/references/category-first-principles.md`。

### 2. RED

先加入方法级回归测试。初次运行 5 项中 4 项失败：

- 缺少多范畴第一性参考模块；
- 准入必要性与网络位置没有分成两轴；
- 华罗庚统筹只剩“关键路径”标签，缺少虚任务、时差、资源、三点估时和重排；
- Agency Protocol 没有声明该方法是可选推理机制，而不是第四道闸门。

这组失败把需求从概念偏好变成了可验证行为。

### 3. GREEN

完成改造后，方法级测试 5/5 通过，仓库全量测试 51/51 通过；补入本案例与模式的证据测试后，预期总数变为 52/52。

主要变化：

- 用 `Required / Optional / Conditional / Reject` 表达准入裁决；
- 用 `Main-contradiction / Parallel / Post-terminal / None` 表达执行位置；
- 允许一条或多条主要矛盾线；
- 专家只负责从范畴独立推演，不成为项目网络节点；
- 分歧转译为可执行、可验收的证据任务；
- 人类价值 Open 与事实/因果 Open 分流；
- 保持 Agency Contract v0.1，不无证据扩展契约字段。

### 4. 无上下文独立测试

进行了两次互不共享本轮上下文的独立测试：

#### 价值边界

输入是“把官网做得更高级、更有生命力，但不要像普通 AI 官网，并直接推进”。

独立执行正确识别：

- `vibe-craft` 与 `vibe-flow` 是主矛盾线上的必要技能；
- `skill-craft` 在该交付任务中应拒绝进入执行网络；
- 这是人的价值判断，不应触发多范畴第一性推演；
- 候选技能里没有真正的前端实现者时，应报告能力缺口，不能让方法论技能越权实现。

#### 因果路由

输入是对长任务漂移的三个假设进行判断：Agency Contract 不足、阶段责任不清、安装漂移。

独立执行正确识别三个不重复范畴：契约状态连续性、阶段责任控制、运行时安装物身份；没有投票或强制共识，而是把分歧变成证据任务。它还区分了两条主要矛盾线：行为漂移因果线与安装一致性线。

测试发现一个真实问题：`skill-craft`、`vibe-craft` 未安装，`vibe-flow` 的安装目录与仓库版本冲突。这证明安装版本漂移真实存在；但它不能单独证明 Agency Contract 是长任务内部漂移的根因。

## 审计

- P0：0
- P1：实际安装物与仓库不一致，必须在交付前备份旧版并重新链接。
- P1：缺少同一长任务在改造前后的可比基线，因此不能宣称已彻底解决长任务漂移。
- P2：现有状态命令能报告 missing/conflict，但不能直接展示来源、版本或内容摘要；本轮不扩展安装工具。

## 输出 Y

- 重写 `skills/vibe-flow/SKILL.md`，使其成为紧凑的路由与统筹守门员；
- 新增 `skills/vibe-flow/references/category-first-principles.md`；
- 同步 `protocol/README.md`、根 `README.md` 与 `agents/openai.yaml`；
- 新增方法级自动化测试；
- 将本轮证据写回 Skill-Craft 的案例库和模式库。

## 提炼规则

1. 新概念不自动等于新技能；先判断它是否有独立触发、独立终态和独立消费者。
2. 专家不是统筹网络的任务节点；专家分歧应转成证据任务。
3. 人类价值判断与事实、因果、预测不确定性必须走不同路由。
4. “是否必要”和“放在哪里执行”必须分成两个正交裁决。
5. 主要矛盾线可以有多条，但每条都要有唯一阶段负责人、继续闸门和重开条件。

## 结论边界

本案例证明的是：结构约束通过自动化测试，且两个独立场景能做出预期路由。它尚未证明生产环境中的长期效果、令牌消耗下降幅度，也未证明任一单独机制足以消除长任务漂移。

# 模式：条件化推理模块

## 触发条件

当一套新的概念方法看起来“到处都能用”，同时出现以下信号时使用本模式：

- 它与现有技能的目标、触发条件或消费者高度重叠；
- 它只在某类不确定性出现时才有价值；
- 单独创建技能会复制既有闸门、交接或上下文；
- 它本身不产生可独立验收的终态，只改善现有技能的判断过程。

## 核心判断

先问三个问题：

1. 它有没有现有技能不能覆盖的独立触发条件？
2. 它有没有独立终态和明确消费者？
3. 用户能不能在不先调用另一个技能的情况下，合理地单独请求它？

如果多数答案是否定的，它应当成为既有技能下的条件化推理模块，**不是第四个技能**。

## 核心动作

1. 找到对最终裁决、交接或产物负责的拥有者技能。
2. 在拥有者的 `SKILL.md` 中只写触发闸门、跳过条件、硬约束和引用路径。
3. 把完整方法、模板、术语解释和示例放进 `references/`。
4. 让调用条件与不调用条件都可测试，防止每次任务都机械展开昂贵推理。
5. 保留现有数据契约；只有消费者证据表明字段不足时才升级契约版本。
6. 用无上下文测试至少覆盖：
   - 一个应触发该模块的事实、因果或预测场景；
   - 一个应跳过该模块的人类价值或简单执行场景。

## 结构模板

主技能负责：

- 何时调用；
- 何时跳过；
- 谁拥有最终裁决；
- 输出如何进入现有契约；
- 违反边界时如何重开。

参考模块负责：

- 视角或范畴如何选择；
- 每个视角如何独立推演；
- 分歧如何显式化；
- 如何把分歧转成证据任务；
- 如何形成稳健交集、条件化结论和概率说明。

## 证据

- [案例 003：Vibe-Flow 范畴第一性与华罗庚统筹改造](../cases/003-vibe-flow-category-coordination.md)

该案例中，多范畴第一性推演没有独立终态，其输出直接服务于 Vibe-Flow 的准入、排序和交接裁决。将其下沉为参考模块后，人的价值判断场景能正确跳过，事实因果场景能正确触发。

## 例外

当新方法后来形成了真正独立的用户请求、独立终态、独立消费者和不同生命周期时，可以升级为单独技能。升级前仍需用真实案例证明：拆分减少了耦合或上下文，而不是只增加了一个名字。
